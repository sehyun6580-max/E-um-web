## 4. 평소 작업 흐름

```bash
git checkout main && git pull          # 1. 최신 코드 받기
git checkout -b feat/짧은-설명          # 2. 작업용 브랜치 만들기
# ... 수정 ...
npx tsc --noEmit && npx eslint src && npm run build   # 3. 검사
git add -A && git commit -m "무엇을 왜 바꿨는지"       # 4. 커밋
git push -u origin feat/짧은-설명                      # 5. 올리기
gh pr create                                         # 6. PR 만들기 (GitHub 웹에서 해도 돼요)
```

7. PR에 Vercel 봇이 **미리보기 주소**를 달아 줘요. 그 주소에서 데스크톱과 휴대폰으로 확인해요.
8. 괜찮으면 PR을 **Merge**해요. `main`에 들어가면 실제 사이트가 바뀌어요.

- 혼자 작업하더라도 PR을 거치면 미리보기로 먼저 확인할 수 있어서 실제 사이트가 깨질 일이 줄어요.
- 배포가 실패하면 PR이나 커밋 옆에 빨간 ✗가 떠요. 방법 B로 넘겼다면 Vercel의 **Deployments → 해당 배포 → Build Logs**에서 이유를 볼 수 있어요.

### API

| 주소 | 하는 일 | 모델 |

| 초안 채우기 | "세 칸의 초안" (표에서는 세 번째 칸을 사용자가 작성) | 앞의 두 칸만 채워요 | 결론은 사용자가 쓰도록 일부러 비워 둬요 |
| 소개 웹사이트 | 없음 | `/`에 새로 추가 | FAQ 포함 |
| 코드 노출 차단 | Streamlit 메뉴와 오류 코드 숨김 | 해당 없음 | 서버 코드와 키는 브라우저에 노출되지 않아요. 저장소는 공개예요 |
| 화면 구성, 모드, 컨트롤러, 단계, 러브레터, 포스트잇 | 기능설명서 내용 | 같아요 | 6:4, 72% 제목, 640px 기준, 동작 줄이기까지 반영했어요 |

## 7. 할 일 목록 (우선순위 순)

1. **[높음] 입장 비밀번호 (`APP_PASSWORD`)**
   - 환경 변수에 비밀번호가 있으면 서버에서 `/api/chat`, `/api/flip`, `/api/draft`를 막고, 비밀번호를 아는 사람만 쓰게 해요.
   - 기능설명서에 있던 기능이고, 비용을 막는 가장 쉬운 방법이에요. 비밀번호 확인은 반드시 **서버**에서 해야 해요.
   - 브라우저 localStorage에 저장하는 지금의 로그인으로는 막을 수 없어요.
2. **[높음] API 사용 금액 한도**: Anthropic Console과 OpenAI 결제 설정에서 월 한도를 걸어요.
3. **[중간] 소개 페이지 '왜 만들었냐면요' 문구**: 이전 담당이 임시로 쓴 초안이에요. 팀의 실제 이야기로 바꿔 주세요. 서명도 "이음을 만든 사람들"로 임시로 넣어 뒀어요.
4. **[중간] 기능설명서 고치기**: 5쪽 기술 구성과 6장 대응표의 차이를 반영해요.
5. **[중간] 실제 대화로 프롬프트 다듬기**
   - 여러 고민으로 F/T 모드를 각각 6턴 이상 해 보면서 아래를 확인해요.
     - 질문이 너무 많지 않은지
     - 마무리가 자연스러운지
     - 다른 시선 질문이 겹치지 않는지
   - 고치는 곳은 `prompts.ts`예요.
6. **[낮음] 사용 횟수 제한**: 한 사람이 너무 많이 호출하지 못하게 해요. Vercel에서는 별도 저장소(예: Upstash)가 필요할 수 있어요.
7. **[낮음] 계정과 기록을 서버에 저장**: 다른 기기에서도 이어서 보려면 Supabase나 Vercel Postgres 같은 DB와 진짜 로그인이 필요해요. 개인정보 안내도 함께 바뀌어야 해요.
8. **[낮음] 공유용 정보 다듬기**: 링크를 공유할 때 보이는 미리보기 이미지와 사이트 아이콘(파비콘)이 아직 기본값이에요.
9. **[낮음] 자동 테스트**: 지금은 없어요. `reply.ts`의 파싱 함수부터 테스트를 붙이면 좋아요.

## 8. 자주 막히는 곳

| 증상 | 원인과 해결 |
| --- | --- |

| "요청이 몰려 잠시 막혔어요" | 사용량 제한(429)이에요. 잠시 뒤 다시 시도하거나 콘솔에서 한도를 확인해요 |

| `AGENTS.md`가 혼자 바뀜 | `next dev`가 자동으로 쓰는 파일이에요. 그대로 커밋해도 돼요 |
| 로그인 비밀번호를 잊음 | 브라우저에만 저장돼서 되찾을 수 없어요. 새 비밀번호를 적고 '같은 이름으로 새 공간 만들기'를 누르면 빈 공간으로 새로 시작해요 |

| 시크릿 창에서 로그인 안 됨 | 저장소(localStorage)를 막는 브라우저 설정이에요. 일반 창으로 열어요 |

## 9. 왜 이렇게 만들었나 (결정 기록)

- **Streamlit에서 Next.js로**: GitHub·Vercel 배포를 원했는데, Vercel은 Streamlit 같은 Python 서버를 계속 띄울 수 없어서 새로 만들었어요. 이전 담당이 기존 앱은 두고 새로 만들자고 정했어요.
- **F는 Claude, T는 OpenAI**: 기능설명서의 모델 구성을 그대로 따랐어요. 짧은 상담 답변이라 Claude 호출은 `effort: low`로 비용과 속도를 아꼈어요.
- **태그 형식 출력**: 제목, 본문, 다른 시선을 안정적으로 나누면서 글자가 생성되는 대로 보여주려고 태그를 쓰고, 스트리밍 중에도 잘라서 보여줘요.
- **데모 로그인**: 이전 담당이 '로그인해서 사람마다 따로 쓰기'를 요청했어요. 서버 DB 없이 바로 시연할 수 있도록 브라우저 저장소를 썼어요. 실제 서비스로 키우려면 7장 7번이 필요해요.
- **소개 페이지**: 이전 담당이 uwellnow.com 느낌의 서비스 소개 사이트를 원했고, FAQ가 있는 팀 사이트 구성을 참고하자고 했어요. 문구는 기능설명서를 쉬운 해요체로 풀었어요.
- **키가 없어도 동작**: 협업자가 키 없이도 화면 작업을 할 수 있게 예시 답변 모드를 넣었어요.
